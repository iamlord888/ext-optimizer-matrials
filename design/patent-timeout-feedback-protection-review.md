# 专利 PPT 内容复核与拟保护点修订建议

核对日期：2026-10-12。对象为本轮提供的 PPT 文字、当前工作树中的反馈实现及相关专利原文。[英文对照](patent-timeout-feedback-protection-review-en.md)；[专利原文定位与技术对照](patent-timeout-feedback-primary-review-20261012.md)。

目前材料已经讲清楚限时执行和下一轮反馈的主流程。需要优先修正的是行数的适用条件、精确值与下界的合并规则，以及对已有专利的区别表述。拟保护点建议围绕“取消时保存实际执行计划和节点统计，经计划核对、行数判定和跨轮合并，形成下一轮候选的基数输入”组织；其中取消后仅重新规划、整轮核对后才写入统计，是当前代码中值得突出的一条具体处理路径。

## 1. 已有材料中需要改进的内容

| 位置 | 当前表述的问题 | 建议修改 |
| --- | --- | --- |
| 背景：“浪费一次昂贵的执行尝试” | 超时取消本身可以节省调优时间；问题是已有节点统计未被后续调优使用 | 改为“正常结果返回被中断，本轮已产生的节点统计难以继续用于调优” |
| 背景：“部分有价值的基数” | 取消时取得的是节点已返回行数，其中一部分只是下界 | 改为“超时前已产生可用于反馈的节点行数信息” |
| 技术方案 1 | 未明确初始配置和停止条件，容易理解成每次取消都一定进入下一轮 | 写明当前实验初始上限为 10 秒；有可用反馈且未满足停止条件时继续。正常完成也产生行数反馈 |
| 技术方案 2：“判定 EOF” | 本地 EOF 不直接证明下一轮待修正的扫描或连接已经返回全部结果 | 保留 `active`、`terminal` 的字段来源，并说明仍需检查再次调用及计数范围 |
| 技术方案 2：“核对候选 SQL 计划结构” | 没说明核对的两个计划从哪里来，也省略了不再次执行查询的关键步骤 | 写明取消现场的实际执行计划与相同候选 SQL 重新规划所得计划；全部匹配后才写入统计 |
| 技术方案 3：“未返回” | 容易把未执行与已执行但实际返回零行混为一谈 | 改为“未执行、统计无法直接比较，或仅返回部分行数且 A ≤ E” |
| 技术方案 3：下界直接 `max(Bᵢ(k), A)` | 已有精确值时，当前实现不允许新下界覆盖精确值 | 增加“尚无精确值时取较大值；已有精确值时保留精确值” |
| 示例中的 2,400 | 仅知道采样值为 5,000，无法推出 `A=2,400` 符合 `A>E`；本轮 E 与历史 Hint 也不能直接等同 | PPT 简化为“5,000 → 合格下界 6,400 → 精确值 7,200”。保留 2,400 时另说明本轮 E 和接受条件 |

背景还可以增加一个来自现有实验的具体候选：查询编号、关键算子的 E/A、超时发生位置及取消后的结果返回。当前性能对照可以支持调优总时长的观察，不能代替所有节点行数都可正确反馈的验证。说明性的数值例子应明确标为例子。

需要补齐的三项条件：确认节点的相关调用已经返回全部结果；使累计行数和估算行数覆盖相同执行次数；确认跨候选复用的统计对应相同查询条件、连接语义及数据。无法证明时，应限定支持范围或不反馈。Nested Loop 内侧扫描已有部分限制，但其内侧连接仍可进入反馈，不能认为这些条件已经由现有收集函数完整保证。

两个说明性反例：第一次本地 EOF 后，Nested Loop 的下一条外侧行可能再次调用内侧节点；某节点单次估算 100 行，两次各返回 80 行，累计 160 行大于 100，并不能证明单次估算偏低。不能直接用 `nloops` 相除解决全部问题，因为它也不一定包含当前尚未结束的调用。

另外，原始零行观测与 Hint 的输出值需要区分：当前代码保留 `EXACT(0)`，但 Hint 输出至少为 1。[输出转换](../contrib/hint_adviser/hint_adviser_rows_state.c#L30)。“内部下界增强”也不等于“规划输入变化”；本轮所有 Hint 输出均不变时，现有循环会按收敛停止。[停止条件](../contrib/hint_adviser/hint_adviser_feedback_policy.c#L99)

## 3. 技术方案 2 的建议替换文字

**本 Idea 的技术方案 2：取消时采集节点统计并核对执行计划**

**核心处理：在执行器清理前保存本轮实际执行计划、节点行数和执行状态；计划核对通过后，将统计用于行数反馈。**

1. **保存算子对象：** 从 `QueryDesc.planstate` 取得顶层 `PlanState`，遍历执行计划状态树，保存算子对象。
2. **读取统计：** 从 `PlanState.plan` 读取节点 ID 和估算行数 E；从 `PlanState.instrument` 读取累计返回行数 A、Loops 及执行状态。
3. **记录本地 EOF：** `active=false` 表示当前没有正在进行的 `get_next` 调用；此时 `Instrumentation.status != 0`，则记为 `terminal=true`。本地 EOF 仍需结合再次调用及计数范围判断。
4. **核对并写入：** 返回本轮实际计划文本与统计。取消结束后，对同一候选 SQL 用不带 `ANALYZE` 的 `EXPLAIN` 重新规划；核对节点 ID、算子、查询块、估算行数及层次，全部通过后写入统计，否则拒绝本轮反馈。

讲解时应明确：步骤 4 的重新规划用于补全本轮计划结构；之后加入新 Rows Hint 生成的才是下一轮候选。节点 ID 用于本轮原计划与重新规划结构的对应，跨轮反馈则按查询块及扫描/连接对象合并，不能跨轮直接复用物理节点 ID。

## 4. 技术方案 3 的建议替换文字

**本 Idea 的技术方案 3：节点行数反馈的判定与合并**

**更新原则：精确行数可上调或下调；合格下界只抬高；没有合格统计时保持原值。** A、E 必须对应同一扫描或连接，并覆盖可直接比较的执行次数。

| 判定条件 | 反馈类型 | 下一轮 Rows Hint 更新 |
| --- | --- | --- |
| 可确认该扫描或连接已返回全部相关结果 | `EXACT(A)` | 用 A 更新，并清除旧下界 |
| 尚不能确认结果完整，已输出量是同一目标的行数下界，且 A > E | `LOWER_BOUND(A)` | 尚无精确值时，取已有 Hint 与 A 的较大值；已有精确值时保留精确值 |
| 未执行、统计无法直接比较，或仅返回部分行数且 A ≤ E | `NONE` | 保持已有 Hint |

**合并规则：** 精确值优先于下界；多个下界取最大值；采样值不覆盖已有执行证据。新下界超过已有精确值时，当前实现保留精确值并记录矛盾。

**更新示例：** 初始采样为 5,000；取得合格下界 6,400，Hint 提高到 6,400；取得精确行数 7,200，更新为 7,200 并清除旧下界。

该表表示拟采用的严格判定规则。当前代码的本地 EOF 与 `A>E` 分类仅覆盖其中部分条件，剩余条件应在交底书的实施说明中明确。零行 Hint 编码、同轮多个精确值的处理，以及数据或查询条件变化后的证据失效，可放入讲解备注。

## 6. 拟保护点的优化建议

### 6.1 可直接用于一页 PPT 的文字

**拟保护点：取消时节点统计的校验与跨轮基数反馈**

**核心机制：将限时取消取得的节点统计，经原计划核对、行数判定和跨轮合并，转为下一轮候选的基数输入。**

1. **清理前保存执行事实：** 候选达到期限被取消时，在执行器对象有效期间取得本轮实际执行计划、节点行数和执行状态。
2. **核对原计划后使用统计：** 对同一候选 SQL 仅重新规划，核对原计划与新计划结构；全部匹配才写入统计，不一致则拒绝本轮反馈。
3. **按行数类型合并：** 对可直接比较的扫描或连接，完整行数替换旧值，合格下界只抬高，无合格统计保持原值；精确值优先，多个下界取最大值。
4. **用于下一轮独立候选：** 正常完成与超时取消均可提供行数反馈；完整运行时间用于比较最佳候选，并据此调整后续执行期限。

**进一步限定：** 排除再次调用和累计计数导致的误用；单轮期限同时受配置上限、最佳完整时间与剩余调优预算约束。

讲解备注：第 2 点及跨轮合并已有代码支撑；第 3 点中的严格适用条件、以及“排除再次调用和累计计数误用”，仍需补齐实现和验证。

### 6.2 主保护与从属条件的组织

主保护组合应保留连续的数据依赖：期限取消触发采集；取消现场的原计划为统计对应提供依据；对应检查成功后才判定行数是否适用；行数类型决定更新方向与合并方式；合并结果用于下一轮独立规划。

可以将“取消后只重新规划、全部结构一致后才写入统计”组织为较具体的保护版本。这一版本的实现依据最清楚，也更直接说明：重新生成的计划不能自动代表实际执行过的计划。为兼顾直接保存完整原计划结构的其他实现，更一般的版本可描述为“将取消统计与本轮实际计划核对后，形成可用于反馈的计划结构”，将不带 `ANALYZE` 的补全步骤作为进一步限定。更一般的版本与已核专利重合更大，不能仅因措辞扩大就认为保护更强。

| 层次 | 建议内容 |
| --- | --- |
| 主组合或具体保护版本 | 清理前取得原计划事实、取消后计划补全与对应校验、按适用条件分类、按修正对象跨轮合并、下一轮独立候选消费 |
| 重要从属条件 | 本地 EOF 之外检查再次调用；单次与累计计数换算或拒绝；无精确值时下界累计取最大；精确值优先；未执行与零行分开；不一致统计不发布 |
| 调优控制从属条件 | 配置上限与最佳完整时间乘倍率的较小值；全局剩余预算及收尾预留；只有完整时间更新最佳候选 |
| 具体实施例 | `QueryDesc`、`PlanState`、`Instrumentation`、JSON、计划文本、消息传输、Rows Hint，以及当前 10 秒和 1.25 的取值 |

10 秒、1.25、三种标签、外部服务和同一 SQL，均不宜单独承担主要技术区别。保护文字可将倍率写为参数 α，实施例使用 1.25；字段名及文件格式用于解释实现，不必使一般方法仅覆盖 GaussDB 507。

### 6.3 支撑技术效果的具体场景

建议优先补充四类可观察对照：相同候选重新规划后结构改变，统计被拒绝；本地 EOF 后仍需再次调用，行数不被误作最终值；累计 A 大于单次 E，但单次实际小于 E，不错误抬高 Hint；已有精确值时新下界不覆盖，未执行与真实零行得到不同处理。

这些场景分别支持计划核对、行数判定和合并机制的必要性。现有性能汇总不等价于完成这些验证。本轮只复核代码与文稿、提出保护建议，没有修改代码行为，也没有新增或运行数据库实验。现有文献中未核到上述具体处理链的完整披露，但匹配、状态分类与已有反馈机制的组合仍需要进一步检索和论证，不能把“单篇未找到”当作已证明新颖性或创造性。
