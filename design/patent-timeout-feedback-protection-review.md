# 专利 PPT 内容复核与拟保护点修订建议

核对日期：2026-10-12。对象为本轮提供的 PPT 文字、当前工作树中的反馈实现及相关专利原文。[英文对照](patent-timeout-feedback-protection-review-en.md)；[专利原文定位与技术对照](patent-timeout-feedback-primary-review-20261012.md)。

目前材料已经讲清楚限时执行和下一轮反馈的主流程。需要优先修正的是行数的适用条件、精确值与下界的合并规则，以及对已有专利的区别表述。拟保护点建议围绕“限时取消时读取节点统计，判定行数是否适用，按反馈类型跨轮合并并修正下一轮基数”组织。取消后重新规划及与原计划匹配属于当前实现的安全防护，保留在实施说明中，不列入拟保护点。

## 1. 已有材料中需要改进的内容

| 位置 | 当前表述的问题 | 建议修改 |
| --- | --- | --- |
| 背景：“浪费一次昂贵的执行尝试” | 超时取消本身可以节省调优时间；问题是已有节点统计未被后续调优使用 | 改为“正常结果返回被中断，本轮已产生的节点统计难以继续用于调优” |

| 技术方案 1 | 未明确初始配置和停止条件，容易理解成每次取消都一定进入下一轮 | 写明当前实验初始上限为 10 秒；有可用反馈且未满足停止条件时继续。正常完成也产生行数反馈 |
| 技术方案 2：“判定 EOF” | 本地 EOF 不直接证明下一轮待修正的扫描或连接已经返回全部结果 | 保留 `active`、`terminal` 的字段来源，并说明仍需检查再次调用及计数范围 |
| 技术方案 2：“核对候选 SQL 计划结构” | 没说明核对的两个计划从哪里来，也省略了不再次执行查询的关键步骤 | 写明取消现场的实际执行计划与相同候选 SQL 重新规划所得计划；全部匹配后才写入统计 |
| 技术方案 3：“未返回” | 容易把未执行与已执行但实际返回零行混为一谈 | 改为“未执行、统计无法直接比较，或仅返回部分行数且 A ≤ E” |
| 技术方案 3：下界直接 `max(Bᵢ(k), A)` | 已有精确值时，当前实现不允许新下界覆盖精确值 | 增加“尚无精确值时取较大值；已有精确值时保留精确值” |
| 示例中的 2,400 | 仅知道采样值为 5,000，无法推出 `A=2,400` 符合 `A>E`；本轮 E 与历史 Hint 也不能直接等同 | PPT 简化为“5,000 → 合格下界 6,400 → 精确值 7,200”。保留 2,400 时另说明本轮 E 和接受条件 |

背景还可以增加一个来自现有实验的具体候选：查询编号、关键算子的 E/A、超时发生位置及取消后的结果返回。当前性能对照可以支持调优总时长的观察，不能代替所有节点行数都可正确反馈的验证。说明性的数值例子应明确标为例子。

需要补齐的三项条件：确认节点的相关调用已经返回全部结果；使累计行数和估算行数覆盖相同执行次数；确认跨候选复用的统计对应相同查询条件、连接语义及数据。无法证明时，应限定支持范围或不反馈。Nested Loop 内侧扫描已有部分限制，但其内侧连接仍可进入反馈，不能认为这些条件已经由现有收集函数完整保证。

两个说明性反例：第一次本地 EOF 后，Nested Loop 的下一条外侧行可能再次调用内侧节点；某节点单次估算 100 行，两次各返回 80 行，累计 160 行大于 100，并不能证明单次估算偏低。不能直接用 `nloops` 相除解决全部问题，因为它也不一定包含当前尚未结束的调用。

另外，原始零行观测与 Hint 的输出值需要区分：当前代码保留 `EXACT(0)`，但 Hint 输出至少为 1。[输出转换](../contrib/hint_adviser/hint_adviser_rows_state.c#L30)。“内部下界增强”也不等于“规划输入变化”；本轮所有 Hint 输出均不变时，现有循环会按收敛停止。[停止条件](../contrib/hint_adviser/hint_adviser_feedback_policy.c#L99)

## 3. 技术方案 2 的建议替换文字

**本 Idea 的技术方案 2：超时返回节点行数与执行状态**

**核心处理：超时取消时，在执行器清理前读取并返回节点行数和执行状态，供后续行数反馈判定。**

1. **保存节点对象：** 从 `QueryDesc.planstate` 取得顶层算子的 `PlanState`，遍历执行计划状态树并保存节点指针。
2. **读取行数：** 从 `PlanState.plan` 读取节点 ID 和估算行数 E；从 `PlanState.instrument` 读取累计返回行数 A 和 Loops。
3. **读取执行状态：** 根据 `Instrumentation` 的调用起始时间判断 `active`。`active=false` 表示没有正在进行的 `get_next` 调用；此时若 `Instrumentation.status != 0`，则记为 `terminal=true`，表示本地已读到 EOF。
4. **返回本轮统计：** 返回实际执行计划文本、节点行数及执行状态，供客户端进行行数判定并更新后续基数反馈。

**本地 EOF 不直接等于精确行数，还需检查节点是否会再次执行，以及实际与估算行数能否直接比较。**

当前客户端通过对完全相同的本轮候选 SQL 仅重新规划，取得计划结构并核对原计划后，将统计写入对应节点。这是实施说明中的防护流程，不列入拟保护点。重新规划用于补全本轮计划结构；之后加入新 Rows Hint 生成的才是下一轮候选。节点 ID 用于本轮统计对应，跨轮反馈则按查询块及扫描/连接对象合并。

## 4. 技术方案 3 的建议替换文字

**本 Idea 的技术方案 3：节点行数反馈的判定与合并**

**更新原则：精确行数可上调或下调；合格下界只抬高；没有合格统计时保持原值。** A、E 必须对应同一扫描或连接，并覆盖可直接比较的执行次数。

| 判定条件 | 反馈类型 | 下一轮 Rows Hint 更新 |
| --- | --- | --- |
| 可确认该扫描或连接已返回全部相关结果 | `EXACT(A)` | 用 A 更新，并清除旧下界 |
| 尚不能确认结果完整，已输出量是同一目标的行数下界，且 A > E | `LOWER_BOUND(A)` | 尚无精确值时，取已有 Hint 与 A 的较大值；已有精确值时保留精确值 |
| 未执行、统计无法直接比较，或仅返回部分行数且 A ≤ E | `NONE` | 保持已有 Hint |

**合并规则：** 精确值优先于下界；多个下界取最大值；采样值不覆盖已有执行证据。新下界超过已有精确值时，当前实现保留精确值并记录矛盾。

**更新示例：** 初始采样为 5,000；取得合格下界 6,400，Hint 提高到 6,400；取得精确行数 7,200，更新为 7,200 并清除旧下界。

该表表示拟采用的严格判定规则。当前代码的本地 EOF 与 `A>E` 分类仅覆盖其中部分条件，剩余条件应在交底书的实施说明中明确。零行 Hint 编码、同轮多个精确值的处理，以及数据或查询条件变化后的证据失效，可放入讲解备注。

## 6. 拟保护点的优化建议

### 6.1 可直接用于一页 PPT 的文字

**拟保护点：限时执行中的节点行数判定与跨轮反馈**

**核心机制：在候选超时取消时取得节点已有执行统计，按行数的适用条件分类并合并，修正同一 SQL 下一轮候选的基数输入。**

1. **限时取消时保留统计：** 候选达到单轮期限被取消时，在执行器清理前取得节点估算行数、已返回行数及执行状态。
2. **判定可反馈的行数：** 根据执行状态、是否还需再次调用，以及实际与估算的计数范围，区分精确行数、可用下界和无反馈。
3. **按反馈类型跨轮合并：** 精确行数可上调或下调；合格下界只抬高；无合格统计保持原值。精确值优先于下界，多个下界取最大值。
4. **修正下一轮候选：** 将合并结果用于同一 SQL 的下一轮独立规划。正常完成也可提供行数反馈；完整运行时间用于比较最佳候选和调整后续期限。

**进一步限定：** 尚未返回全部结果的节点，只有实际行数和估算可直接比较且 A > E 时才以合格下界抬高基数；单轮期限同时受配置上限、最佳完整时间和剩余调优预算约束。

讲解备注：当前已有取消统计采集、状态分类和跨轮合并。第 2 点中的再次调用检查及累计计数处理仍需补齐实现和验证。

### 6.2 主保护与从属条件的组织

主保护组合保留“期限取消 → 清理前读取节点统计 → 行数适用判定 → 按反馈类型合并 → 下一轮基数修正”的连续数据依赖。取消时存在的统计决定能否形成精确值或下界；反馈类型决定更新方向与合并方式；合并结果交给下一轮独立规划。

当前客户端的重新规划、原计划匹配和整轮拒绝机制，解决的是统计与恢复计划之间的对应问题，放在实施说明中。它们不列为本次拟保护点，也不作为方法成立的必要步骤。其他实现可以直接取得结构化的原计划及节点统计，因此不应把保护范围限定为必须重新规划或必须匹配两份计划。统计仍需对应正确的扫描或连接；这一行数适用前提不等于要求执行现有的重规划匹配流程。

| 层次 | 建议内容 |
| --- | --- |
| 主组合 | 限时取消触发节点统计采集；按结果是否完整及计数范围判定行数；分级合并；同一 SQL 下一轮独立候选消费 |
| 重要从属条件 | 本地 EOF 之外检查再次调用；单次与累计计数换算或拒绝；仅以合格 A > E 下界提高基数；无精确值时下界累计取最大；精确值优先；未执行与零行分开 |
| 调优控制从属条件 | 配置上限与最佳完整时间乘倍率的较小值；全局剩余预算及收尾预留；只有完整时间更新最佳候选 |
| 实施说明 | `QueryDesc`、`PlanState`、`Instrumentation`、JSON、计划文本、消息传输、重新规划及计划匹配、Rows Hint，以及当前 10 秒和 1.25 的取值 |

10 秒、1.25、三种标签、外部服务和同一 SQL，均不宜单独承担主要技术区别。保护文字可将倍率写为参数 α，实施例使用 1.25；字段名及文件格式用于解释实现，不必使一般方法仅覆盖 GaussDB 507。

### 6.3 支撑技术效果的具体场景

建议优先补充三类可观察对照：本地 EOF 后仍需再次调用，行数不被误作最终值；累计 A 大于单次 E，但单次实际小于 E，不错误抬高 Hint；已有精确值时新下界不覆盖，未执行与真实零行得到不同处理。重新规划后结构改变而统计被拒绝，可作为当前实现防护的验证。

前三类场景支持行数判定和合并规则的必要性。现有性能汇总不等价于完成这些验证。本轮只调整文稿及保护建议，没有修改代码行为，也没有新增或运行数据库实验。去掉重规划匹配限制后，拟保护组合更贴近限时执行反馈机制；仍需结合已公开的部分执行反馈及行数下界技术，说明具体判定和更新规则的技术作用，不能仅凭“同一 SQL”“超时”或分类标签推断新颖性或创造性。
