# JOB 完整执行总时间差额：逐 SQL 分解

分析日期：2026-10-12。数据为 2026-09-28 的 JOB 113 条 SQL，沿用实验预先指定的第 3 次独立完整运行时间。这里比较的是调优候选的后续完整执行时间，单轮 10 秒上限作用于调优试运行；独立执行评价使用 900,000 ms 的 statement timeout。

**189.691 秒与 168.351 秒之间的 21.340 秒净收益，主要来自 `16b.sql` 的恢复候选。该查询单条节省 25.391 秒；其余 112 条 SQL 合计增加 4.051 秒。** 因此这次总时间下降集中在一个查询，不能表述为所有查询普遍改善。

## 2. 16b 的来源及稳定性

| 执行组 | 第 1 次（秒） | 第 2 次（秒） | 第 3 次（秒） |
| --- | ---: | ---: | ---: |
| 原 SQL | 47.342399 | 46.277432 | 46.572432 |
| 无单轮超时组候选 | 36.371750 | 36.058742 | 36.382811 |
| 10 秒组恢复候选 | 10.887741 | 10.920170 | 10.992180 |

无单轮超时组调优执行 4 轮，最佳候选来自第 2 轮，最后达到全局搜索预算。10 秒组执行 11 轮，全部为部分反馈轮次，`best_iteration=0`，最终状态为 `tuning_failed`。扩展评价从最后的 `final_rowshint_plantrace` 恢复候选，记录含 37 条 Rows Hint，并独立测量其完整执行时间。

三次完整测量均显示约 36 秒对约 11 秒的差异，单次计时波动不足以解释这项主要收益。现有记录可确认候选来源和时间差额；原实验完整执行计划在当前本地及容器的记录路径中不可用，本分析没有重建本次实际计划，也没有将该收益进一步归因到某个连接顺序、连接方法或具体 Rows Hint。两组代码版本不同，结果也不能单独归因于 10 秒参数。

## 3. 次要收益与反向变化

`19d` 的三次测量分别为无超时组 8.247256 / 8.168168 / 8.241688 秒，对 10 秒组 7.575882 / 7.779871 / 7.542029 秒；三次均改善。10 秒组有 11 个部分反馈轮次。

`24a` 的三次测量分别为 0.951750 / 0.927685 / 0.931054 秒，对 0.335574 / 0.338097 / 0.330172 秒；三次均改善。10 秒组有 8 个部分反馈轮次。这些数据说明对应候选的改善稳定，不能单凭轮次数量断定改善只由部分反馈机制导致。

`9d` 没有部分反馈轮次。无超时组前两次为 6.510375 和 6.544955 秒，第 3 次升至 8.135615 秒；10 秒组为 6.739296 / 6.622422 / 6.743242 秒。两组各取中位数时，无超时组为 6.544955 秒、10 秒组为 6.739296 秒，10 秒组反而略慢。因此第 3 次的 1.392373 秒贡献不宜当作稳定优化收益。

`18c` 反向影响最大：恢复候选完整执行为 11.601345 秒，无超时组候选为 7.443910 秒，增加 4.157435 秒；三个重复均显示这一方向。`17e`、`7c`、`30a` 也在三次重复中均变慢。

## 4. 正式交付与扩展评估

168.350794 秒包括 `16b`、`18c` 两条未正式交付的恢复候选。若仅使用正式交付候选，失败查询按原 SQL 回填：

| 调整 | 增加时间（秒） |
| --- | ---: |
| 16b：10.992180 → 原 SQL 46.572432 | +35.580252 |
| 18c：11.601345 → 原 SQL 12.335748 | +0.734403 |

正式交付计算下，10 秒组为 **204.665449 秒**，比无超时组 **189.690550 秒**多 **14.974899 秒**，约多 7.89%。即使只排除 `16b` 一项恢复收益，10 秒组总和也会升至 203.931046 秒。

汇报可以准确写为：“含恢复候选的扩展评估中，JOB 执行总时间减少 21.34 秒，主要来自 16b 恢复候选的 25.39 秒收益；正式交付评价下尚未得到同样改善。”

## English summary

Across the 113 JOB queries, the preselected third complete execution sums to 189.690550 seconds without a per-candidate timeout and 168.350794 seconds with partial feedback, saving 21.339756 seconds. The recovered, undelivered 16b candidate alone saves 25.390631 seconds; the other 112 queries collectively add 4.050875 seconds. All three 16b measurements consistently show roughly 36 versus 11 seconds. Improvements in 19d and 24a repeat across runs; 9d's apparent saving is mainly driven by its third-run timing variation. Recovered 18c, 17e, 7c and 30a offset part of the gain. Replacing the undelivered 16b and 18c recoveries with the original queries increases the timeout group total to 204.665449 seconds. The accounting contribution is verified, while a plan-level causal explanation remains unresolved because the original full plans are unavailable; different code revisions also prevent attributing every difference to the timeout setting alone.
